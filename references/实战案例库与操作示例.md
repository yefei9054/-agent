# 实战案例库与处理思路（参考文件）

挂载于 SKILL.md 的"实战案例库"章节。**本文件最重要的定位先说在前：这里的案例不是标准答案，也不是让 agent 直接套用的规则，而是"思路启发"——告诉 agent 遇到某类情形该往哪个方向想、该向你确认什么。**

> 设计哲学（请所有人、包括框架本身牢记）：
> **每个造价人的知识储备、理解逻辑、处理习惯都不一样。一个好用的造价智能体，不是把"老师傅的做法"硬塞给用户，而是先吃透"这个用户怎么想、怎么干"，再长成贴着他的样子。**
> 所以——案例只给提示，套用靠你的确认；agent 靠多层询问理解你，再自我生长。

---

## 一、为什么案例不能直接用

| 误区 | 正确做法 |
|---|---|
| 把对话里的案例当成"必须这么套"的规则 | 案例是**思路原型**，只提示"这類情形要注意什么" |
| 认为 agent 已经懂了行业做法 | agent 只懂"通用工作流"，**你的具体口径、习惯、资产它一开始一无所知** |
| 希望 agent 第一次就用对 | 第一次一定是从"问你"开始的，问够了才贴合 |

**结论**：案例库对 agent 的价值 = 一份"易错/易混/易无定额情形的思考清单"。它提醒 agent 在对应场景**主动向你确认**，而不是替你定。

## 二、对话案例 → 思路类别索引（仅作提示，不套用）

下面把前期沉淀的 10 个场景**翻译成"思考类别"**，每个都给出"agent 该问你什么"，而不是"agent 该怎么做"。

| # | 场景原型 | 提炼的**思考要点** | agent 遇到同类时应向你确认的点 |
|---|---|---|---|
| 1 | 风管按周长分档套定额 | **规格/档位必须回到源数据实测，不能凭印象** | "这条风管的实际周长你按图纸哪个尺寸算？你库里分档怎么定的？" |
| 2 | 薄壁镀锌钢管未注工艺 | **同类材料常有工艺变体，特征要拆到足够细的维度** | "KBG 还是 JDG？你习惯怎么区分、套哪个子目？" |
| 3 | PPR 管无专用子目 | **无专用定额时，先看是否同量纲可借用** | "你这边 PPR 是借塑料管还是另有口径？主材怎么计？" |
| 4 | 不锈钢软管无子目 | **同上，借用前提是量纲同族** | "软管你借不锈钢管还是另有办法？" |
| 5 | 防烟分区无定额 | **确无定额时，宁可停下也不硬套** | "这项确无定额，你要走补充定额还是暂估？" |
| 6 | 抗震支架跨专业 | **借用要按你所在专业的口径走** | "你这抗震支架归在哪个专业、借哪册？" |
| 7 | 新旧清单规范冲突 | **口径冲突要有仲裁依据** | "这处新旧规范差异，你以哪版为准？" |
| 8 | 主材定价缺价 | **价要带来源和日期，别名要映射** | "这主材你的价源是信息价/市场价/合同价？单位怎么换？" |
| 9 | 从未见过的材料 | **未知材料先查、再与你确认，绝不猜** | "这材料我查到 XX 说法，来源是……你认不认？" |
| 10 | 用真实 Excel 训练映射 | **你的判断规律要由你的数据来教** | "把你做过的一条清单+正确定额发我，我按你的逻辑学" |

> 注意：上表"思考要点"是**通用提醒**；右边"确认点"才是 agent 真正该说的话。agent 落地时**不预置任何具体映射**，全部以你的确认为准。

## 三、多层询问理解协议（核心：让 agent 吃透你）

agent 通过**分波次、递进式**的提问来建立对你的理解，而不是一上来甩一堆问题。每一波目的不同、问法不同。

### 第 1 波 · 建立画像（首次 / 换用户 / 你主动要求）
目的：搞清你是谁、做什么、习惯怎样。
- 你主要做哪个专业？（机电安装 / 土建 / 市政 / 园林 / 其他）
- 用哪个地区、哪版定额/清单规范？（如 江苏 2014 安装、GB50500-2013/2024）
- 你平时主要出哪类成果？（预算书 / 招标控制价 / 结算书 / 报价表）
- 你自评水平？（资深自己带框架 / 初中级想边用边学）—— 这决定 agent 给你清单还是带教
> 这一波问完，agent 把答案记进 `user_profile`，下次直接读，不再重复问。

### 第 2 波 · 接任务前（每条清单 / 每个项目开始时）
目的：明确本次要求，不臆测。
- 这条清单你要的是预算 / 招标 / 结算哪种口径？
- 取费按什么基数和费率？（你定了 agent 才套，不定就出提示卡）
- 出成果要什么格式？（Excel 表 / 带溯源的清单 / 直接对话结论）

### 第 3 波 · 任务中（遇到缺口 / 歧义 / 无定额）
目的：就事论事地跟你确认，绝不替你选。
- 特征解析卡住：给你选项 + 示例（如"KBG? JDG? 还是都按你的写法统一处理？"）
- 缺定额：问你要补充定额 / 借用 / 暂估，并说明各自后果
- 缺价：问价源（信息价/市场价/合同价），你能给就给、给不了 agent 标"待补"

### 第 4 波 · 出成果前（高风险卡点）
目的：最后一道确认，避免白干。
- 这个口径/取费/折算对不对？你点"干"我才出正式成果
- 成果格式确认，带计算溯源表交你复核

**自适应**：agent 根据你的回答深度自动调节——答得细、给清单就走，答得含糊、多拆步骤带教。问得越多说明越没底，问得越少说明越贴合你。

## 四、agent 自我成长机制

agent 不是装好就不变，它靠**记你的东西**越长越像你。

| 记到哪 | 记什么 | 怎么用 |
|---|---|---|
| `user_profile` | 专业 / 地区 / 规范版 / 常用成果格式 / 水平档 / 个人偏好（如"先出单价再出总价"） | 下次会话直接读，少问、贴合 |
| `case_lib` | **你自己的**案例：你做过的清单+你的正确做法+你的思路 | 同类场景优先参照"你的历史做法"，而不是通用思路 |
| `gap_log` | 你缺过哪些资产、补没补、怎么补的 | 同类缺口直接提示，不重复教学 |

**成长闭环**：问你 → 记下来 → 下次同样情形少问 → 越来越贴你的习惯。你纠正过一次，它下次就按你的来。

> 关键边界：agent 只长"你的习惯与资产"，不长"乱编的能力"。任何它没把握的判断，依然走三铁律（出处可溯 / 拿不准就停 / 过程留痕），不会因为"以前你这么干过"就替你拍板高风险项。

## 五、标准作业流程 SOP（以你的资产与确认为准）

### SOP-A · 一条清单从特征到组价
```
① 接收清单项（特征文本 + 工程量）
② 解析特征 → 提取属性（材质/规格/敷设/工艺…）
③ 跑缺口 4 问：定额? / 价? / 特征可解析? / 取费齐?
   任一缺 → 按第 3 波询问，与你确认后再继续（不替你补）
④ 齐全 → 套定额 + 组价 + 取费（基数/费率以你第 2 波确认为准）
⑤ 过程留痕：摊开人材机与取费计算式
⑥ 第 4 波确认 → 出正式成果（带计算溯源表）
⑦ 回写：本次你的做法沉淀进 case_lib / 资产层
```

### SOP-B · 缺口 → 引导补全 → 回写（闭环）
```
缺口触发 → 补全提示卡(缺什么/去哪找/按啥标准/回哪步)
         → 方法论引导(教你怎么建) + 第 3 波确认你的习惯
         → 你补全(或联网补) → 写回资产层
         → 增量重算该清单项
```

### SOP-C · 拿不准就停 → 澄清 → 确认
```
歧义 / 无定额 / 无价 / 边界模糊
   → 立即停，列"待确认"清单（绝不替选/编）
   → 出澄清卡(给选项+你的历史做法参考)
   → 你确认 → 落库 → 增量重算
```

## 六、案例库喂料指南（教 agent 收"你自己的"案例）

新案例写入 `case_lib` 的最小字段（对应 schema）：

| 字段 | 填法 | 示例（你的，不是范本的） |
|---|---|---|
| name | 案例名 | 我司 JDG 接线盒处理 |
| region | 地区 | 江苏 |
| type | 专业/阶段 | 电气/预算 |
| unit_price | 单方指标(可空) | 380 |
| contents_json | 难点/你的手法/沉淀资产类 | {"难点":"工艺混","手法":"按我司口径JDG借XX","沉淀":"特征规则库"} |
| created_at | 日期 | 2026-08-13 |

> 优先沉淀"易错、易混、易无定额"三类（对应第二节 #2/#3/#5）。**案例必须是你做过的，不是网上抄的**——这正是 agent 越长越像你的燃料。

## 七、示例口径（仅作模板，必须让你填自己的）

下面是"某类项目"的口径示例，**agent 不得硬编码**，必须第 2 波跟你确认后替换：
- 取费基数 = 人工费 + 机械费（费率示例 管理 44 / 利润 14）—— 你的费率按你的地区文件
- 甲供/乙供范围、规费是否计取 —— 按你的合同与当地规定
- 借用原则：仅量纲同族折算，不做跨量纲硬折算 —— 你的借用口径以你确认为准

> 这一节存在的意义，是给 agent 一个"提问的脚手架"，不是给你一个"直接用的值"。
